
### S01 · Opening

| S01-F01 | 0:00-0:08 | Shopping Copilot is a conversational shopping search agent. It turns a one-off query into a shopping process you can correct. |
| S01-F02 | 0:08-0:20 | Within ten turns, it converges changing shopping intent into trustworthy product results. |
| S01-F03 | 0:20-0:30 | The hard part is not finding more products. It is that users keep adding, revising, and contradicting what they asked for. |

### S02 · Product loop

| S02-F01 | 0:30-0:38 | Traditional search treats every request as a static query, so an old condition can quietly outlive its welcome. |
| S02-F02 | 0:38-0:46 | We treat intent as a changing state and put the difference in one state-driven framework. |
| S02-F03 | 0:46-0:54 | Buying protects your hard constraints. Browsing protects your options. Both run on the same state. |
| S02-F04 | 0:54-1:02 | Three mechanisms do the work: slot-level update, a question that earns its turn, and controlled relaxation. |
| S02-F05 | 1:02-1:11 | Route it, update the valid slots, retrieve, verify, then recommend, clarify, or relax, and keep the trace. |
| S02-F06 | 1:11-1:20 | These are not patches for the hard cases. They run across every scenario, including the easy eighty percent. |

| S03-T01-P02 | 1:25-1:30 | The system reads that as Buying and writes three hard constraints. |
| S03-T01-P03 | 1:30-1:35 | Category, colour, and budget become conditions every result must satisfy. |
| S03-T01-P04 | 1:35-1:40 | It filters first, retrieves and ranks, then verifies before anything is shown. |
| S03-T01-P05 | 1:40-1:45 | Only results that clear every hard constraint reach her. |

| S03-T02-P03 | 1:55-2:00 | She keeps every constraint she already gave. |
| S03-T02-P04 | 2:00-2:05 | The tighter state triggers a fresh retrieval. |
| S03-T02-P05 | 2:05-2:10 | Now only legal Nike candidates come back. |
| S03-T03-P01 | 2:10-2:15 | Then she changes her mind: any brand is fine. |
| S03-T03-P02 | 2:15-2:20 | The system catches the no-preference signal on brand. |
