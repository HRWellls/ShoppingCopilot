# 开发者需要补齐的视频素材支持

产品 Demo 同学不需要开发新的业务能力，但需要开发者提供一组“可核验、可录制、可解释”的素材。以下清单对应 v7 脚本中的镜头。

## 必须提供

| 素材 | 用途 | 最小交付形式 | 验收标准 |
|---|---|---|---|
| 架构闭环图 | 0:30–1:20 架构页 | `05-视频技术可视化素材.md` 的 Mermaid 或导出 PNG | 能看出 route、state、双轨、检索、校验、澄清、放宽和三种出口 |
| 槽位状态样例 | Buying + Override | 三轮 JSON/截图：新增 brand、清除 brand、其余保留 | 明确区分 hard/soft；不把历史文本拼接当成当前状态 |
| FSM 状态样例 | 技术叠加层 | `Understand → Retrieve → Verify → Clarify/Relax → Recommend` | 每个镜头能标出当前状态和下一步 |
| 双轨样例 | Buying / Browsing 对比 | 同一 UI 的 route 标签和各自返回说明 | Buying 展示硬约束先过滤；Browsing 展示场景上下文和多样性 |
| 澄清样例 | 3:10–3:35 | 输入、最高价值缺失槽位、问题文本 | 每轮最多问一个槽位，并能解释“为什么问它” |
| Boundary 样例 | 3:35–3:55 | 空集、放宽级别、预算固定的返回 | 不宣称总能返回最接近商品；有合法候选则返回，否则解释限制 |
| 指标证据 | 3:55–4:35 | 公开集 JSON 摘要和泛化/延迟/成本数字 | 数字可追溯；区分 headline 与 Stage 3 ablation |

## 建议提供

- 一次不含 API key、私有路径、ground truth 和调试堆栈的完整录屏。
- 每个场景的固定输入与期望屏幕文案，保证剪辑重录不会改变口径。
- `parent_asin`、简短标题和价格等合法候选摘要；不要临时截图完整目录。
- 一份“配置边界卡”：`dense_enabled=false`、`llm_enabled=false`、`intent_model_mode=off`，以及静态只读目录、单用户隔离、最多十轮。
- 一份现场故障预案：Demo 启动、场景重播、无结果、浏览器缩放和备用预录文件。

## 不应提供

- 未经 trace 支撑的候选数量变化，例如“300 → 40 → 8”。
- 把公开集指标说成真实转化率，或把 Stage 3 机制消融说成最新 headline 分数。
- API key、`api.env`、私有评测标签、完整商品目录、模型缓存路径。
- 未授权的商品图片、品牌素材和音乐。

## 开发者与产品同学的交接顺序

1. 开发者核验固定输入、状态变化、FSM 和指标数字。
2. 产品同学用 `video/index.html` 按 Buying → Browsing → Clarification → Boundary 彩排。
3. 双方确认画面字幕与当前配置一致，再录制正式旁白。
4. 任何实现或指标变化先改素材文档，再改口播，避免视频与代码分叉。
