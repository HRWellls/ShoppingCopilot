# Shopping Copilot 逐帧视频录制 Runbook

本文件是 4:55 正式 Demo 视频的唯一录制脚本。它与 `D:\tiktok tech jam2026\video\index.html` 的 53 个正式帧一一对应，包含全部英文口播、画面、操作、切屏和 PNG 恢复信息。

## 0. 最终录制方案

### 0.1 不需要 PPT

正式画面只使用一个离线浏览器工作台：

```text
D:\tiktok tech jam2026\video\index.html
```

PowerPoint 仅可用于团队已有的片头模板，不是本方案任何正式片段的依赖。Opening、产品闭环、Demo UI、架构状态、指标和 Roadmap 都已经在同一个浏览器工作台中。

### 0.2 录制前一次配置

1. 显示器和 OBS 画布设为 `1920×1080`，浏览器缩放为 `100%`。
2. 双击 `index.html`，确认页首显示 `S01-F01 · 0:00-0:08`。
3. 操作员模式会显示 frame ID、当前英文台词和按键；只用于彩排。
4. 正式录制前按 `F`，进入无控制栏的 clean capture 全屏模式。
5. 主讲人用本文件、打印稿或不在捕获范围内的第二设备阅读英文稿；操作员只按 `Space` 和 `]`。
6. 关闭通知、聊天窗口和自动更新；OBS 只捕获 Edge 窗口或 clean full-screen 显示器。
7. 不启动 Hamburgerr、Python、评测器、网络或 API。

### 0.3 正式操作键

| 功能 | 按键 | 规则 |
|---|---|---|
| 下一正式帧 | `Space` | 一次只前进一帧 |
| 上一正式帧 | `Backspace` | 口播错位时退一帧 |
| 上一/下一段 | `[` / `]` | 直接进入相邻段第一帧并清空上一场景 |
| 本段重置 | `R` | 回到当前段第一帧 |
| 本段终态 | `B` | 故障恢复时跳到当前段最后一帧 |
| 彩排自动 | `P` | 按 manifest 时间推进；正式录制禁用 |
| Clean capture | `F` | 隐藏操作栏并进入全屏；`Esc` 退出 |

### 0.4 一次按键对应什么

每个用户动作固定拆成五帧：

```text
Message
  → Intent
  → Slot Update
  → FSM / Execution
  → Agent Response
```

前三帧不显示 Agent 回复；第四帧解释执行路径；第五帧才显示回复和 Trace。Boundary 只有一个用户请求，空集检测、受控放宽和复核属于内部执行，不伪装成第二条用户消息。

## 1. 口径冻结

- 当前路径：offline rules + local lexical/attribute retrieval and ranking。
- 固定配置：`dense=false`、`llm=false`、`intent model=off`。
- 意图页展示的是规则证据、事件和稳定路由；不得说“模型正在识别意图”。
- Turn execution FSM 是对真实处理顺序和分支守卫的解释性投影，不宣称代码中存在同名枚举类。
- 不展示或口播 `300 → 40 → 8`、`68.675 ms`、summer wedding、总成本为零、总能返回最接近商品。
- 不展示 API key、`api.env`、ground truth、私有标签、完整目录、个人路径、调试堆栈或未授权商品图。
- Stage 3 diagnostic 与 d4 headline 分开；业务价值只能称为待在线验证的假设。

## 3. 架构画面如何读

### 3.1 三个固定区域

```text
Conversation 28% | Architecture trace 44% | Phase inspector 28%
----------------------------------------------------------------
Turn execution FSM: Previous → Event/Guard → Next → Branch reason
```

- Conversation：只显示已发生的消息；Agent 回复在第五帧之前固定为 pending。
- Architecture trace：组件位置不变，只改变 done/active/pending/empty/relax 状态。
- Phase inspector：显示当前阶段的输入输出，不重复整套架构。
- FSM lane：明确前一状态、事件、守卫、下一状态与分支原因。

### 3.2 组件与真实逻辑的对应

| 画面节点 | 解释内容 | 本 Demo 允许展示的输出 |
|---|---|---|
| Rule Parse | 规则结构化解析 | 消息证据和槽位候选 |
| Event Detect | 对话事件检测 | add、clear、no preference、clarification answer |
| Intent Resolve | 稳定 Buying/Browsing 路由 | before/after、retained/changed、规则来源 |
| Slot Reducer | 当前有效状态更新 | before、delta、effective |
| Route Plan | 双轨检索计划 | hard filters、context、soft ranking signals |
| Local Retrieve | 本地属性与 lexical 路径 | 操作名称，不显示虚构候选数量 |
| Hard Verify | 硬约束复核 | legal、too broad 或 empty |
| Policy | 回复策略 | recommend、clarify、relax、constrained response |
| Response | 协议安全回复 | Agent 文本、合法候选或一个问题 |
| Trace | 本轮可验证摘要 | route、槽位/分支和所属证据范围 |

### 3.3 槽位颜色和文字

- 橙色 `hard`：Buying 必须满足；budget 与显式排除项默认固定。
- 绿色 `soft/context`：影响 Browsing 排序和多样性，不直接淘汰全部结果。
- `kept`：上一轮状态继续有效。
- `cleared`：明确清除，旧值不得继续影响检索。
- `fixed`：受控放宽时仍不可静默修改。

### 5.3 浏览器或动态画面失败

1. 停止当前录制。
2. 在 `D:\tiktok tech jam2026\video\assets` 中打开本行同名 PNG。
3. Windows 图片查看器全屏，重新说本行英文，再按编号打开下一张。
4. 后期将补录片段拼回；PNG 内容与动态帧完全相同。
